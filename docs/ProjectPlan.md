# WIMC 项目开发规划

> 说明：除标注“已完成”外，其余功能与性能指标均为待开发计划与待验证目标。

## 1. 目标与非目标
- **目标**：独立进程运行（零 Explorer 注入）、基于公开 GSMTC 与 Win32 API、点击不抢前台焦点、Fluent Design 视觉体验。
- **非目标**：不修改系统任务栏内部 DOM/XAML 结构；不内置本地音频解码器；不承诺免疫未来所有底层公开 API 废弃变更。

## 2. 功能优先级
- **P0（核心）**：GSMTC 会话监听、歌名/歌手/封面读取、播放/暂停/切歌控制、非激活置顶窗口（待原型验证）。
- **P1（重要）**：胶囊态与展开卡片切换、屏幕顶部/任务栏旁路定位、播放进度展示。
- **P2（增强）**：Mica/Acrylic 材质与弹性动画、多显示器选择与开机自启。

## 3. 阶段划分与验收标准
- **Phase 0（文档规范）**：0.1 根目录规范 **[已完成]**；0.2 许可证与 `docs/` 三份设计文档 **[进行中]**。
- **Phase 1（核心与窗口 MVP）[待启动]**：
  - 交付物：三层工程骨架、GSMTC 服务原型、非激活窗口原型。
  - 验收标准：准确读取主流播放器状态与封面；控制响应 < 200ms；在记事本打字时点击浮岛按钮不丢失输入光标；无会话或切换播放器时不崩溃。
- **Phase 2（UI 与动效）[待启动]**：双态平滑切换，不支持透明材质时自动回退纯色圆角背景。
- **Phase 3（定位与适配）[待启动]**：100%~200% DPI 清晰无偏移；全屏应用自动隐藏退避。
- **Phase 4（压测与发布）[待启动]**：性能目标为后台静默 CPU < 0.2%，持续运行工作集内存 < 50MB。

## 4. Phase 1 强制推进顺序
1. 独立验证 GSMTC 媒体读取与控制。
2. 独立验证 Win32 非激活窗口与按钮点击响应。
3. 建立 `Core` / `UI` / `App` 三层工程骨架。
4. 整合最小可用版本 (MVP)。
5. 通过验收后进入 Phase 2。

## 5. 核心风险与应对
- **非激活窗口吞点击事件（高）**：子类化拦截 `WM_MOUSEACTIVATE` 返回 `MA_NOACTIVATE`，在 Phase 1 第 2 步优先实测。
- **封面流内存泄漏（中）**：按 `Title+Artist` 指纹防抖，显式 `using` 释放 `IRandomAccessStream`。
